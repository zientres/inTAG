# TagitalSpace — смарт-контракты TON Testnet

Все команды и адреса в этом каталоге относятся только к **TON Testnet**. Mainnet не используется.

## NFT-коллекция

Контракты `NftCollection.tolk` и `NftItem.tolk` основаны на официальной reference implementation Acton `nft-v1.1` и стандартах:
- TEP-62 — NFT;
- TEP-64 — метаданные;
- TEP-66 — параметры роялти.

Коллекция хранит индекс следующего NFT, метаданные коллекции, код NFT Item и параметры роялти. NFT Item поддерживает чтение данных и передачу владельца. Владелец коллекции (admin) — единственный адрес, который может выпускать NFT и менять admin.

### Изображения и метаданные

- Изображение самой коллекции — `logo.png` сайта TagitalSpace.
- У каждого NFT будет собственное изображение номерного знака с комбинацией, присвоенной этому NFT.
- JSON-файл каждого NFT хранится отдельно в каталоге `metadata/`; поле `image` в JSON указывает на изображение именно этого номерного знака.
- Базовый URL каталога метаданных: `https://zientres.github.io/inTAG/metadata/`.

При выпуске NFT контракт объединяет этот базовый URL с индивидуальным именем JSON-файла. Поэтому метаданные конкретного NFT должны быть опубликованы до его выпуска. GitHub Pages используется для тестовой версии; для production потребуется неизменяемое хранилище, например IPFS или Arweave.

### Подготовка метаданных отдельного NFT

После того как номерной знак выиграл аукцион и ему назначен следующий индекс коллекции, из корня репозитория запустить:

```sh
node scripts/generate-nft-metadata.mjs --index 0 --plate "A777AA 77" --country "Russia" --country-code RUS
```

Вместо примера нужно указать фактический индекс, комбинацию и страну. Генератор создаёт:
- `metadata/[index].json` — TEP-64 metadata;
- `plates/[index].svg` — отдельное изображение номерного знака.

После коммита и публикации через GitHub Pages проверить, что оба URL открываются. Только затем можно выпускать NFT с тем же индексом. Генератор не перезаписывает существующие файлы.

### Администратор

Для первого развёртывания в Testnet администратором временно будет кошелёк создателя. После появления Auction Manager право администратора нужно будет передать его адресу через `ChangeCollectionAdmin`. До этой передачи выпуск NFT доступен только кошельку создателя.

### Роялти

Параметры, задаваемые скриптом развёртывания:
- 2%;
- получатель — кошелёк создателя.

TEP-66 публикует параметры роялти, но не может принудительно заставить сторонние маркетплейсы перечислять их.

## Сборка и тесты

Установить Acton 1.2.0.

```sh
acton build
acton test tests/nft-v1.1
```

В тестовом наборе находятся проверки коллекции, NFT Item, передачи NFT, авторизации и сквозных сценариев.

## Развёртывание коллекции в Testnet

Команда из корня репозитория:

```sh
acton script scripts/deployCollection.tolk --net testnet --tonconnect
```

Скрипт подключит кошелёк и запросит название, описание, URL изображения коллекции и базовый URL JSON-метаданных NFT. По умолчанию уже указаны `logo.png` и каталог `metadata/` на GitHub Pages.

Пользователь подтверждает транзакцию в TON Connect. Перед подтверждением нужно проверить, что кошелёк подключён именно к Testnet.

## Тестовый выпуск NFT в Testnet

После развёртывания коллекции и публикации файлов метаданных можно выполнить прямой тестовый выпуск:

```sh
acton script scripts/mintNft.tolk --net testnet --tonconnect
```

Скрипт:
1. Подключает кошелёк через TON Connect.
2. Проверяет, что подключённый кошелёк является администратором коллекции.
3. Читает следующий индекс NFT из контракта.
4. Формирует имя метаданных `[index].json`.
5. Запрашивает адрес получателя и отдельное подтверждение перед отправкой.
6. Выпускает NFT и проверяет адрес, индекс, коллекцию и владельца.

Этот скрипт предназначен только для контролируемой проверки коллекции в Testnet. Это **не финальный пользовательский mint-процесс**: в готовом продукте выпуск будет вызываться Auction Manager только после завершения аукциона, а не напрямую пользователем.
