# Auction Manager — проектирование (TON Testnet)

## Цель

Auction Manager управляет аукционами TagitalSpace и после завершения торгов выпускает NFT победителю через существующую NFT Collection.

Этот документ фиксирует первую версию логики до реализации контракта и тестов. Он не означает, что права администратора коллекции уже переданы: сейчас admin коллекции — кошелёк создателя.

## Основные правила аукциона

- Один аукцион продаёт право получить один заранее подготовленный NFT номерного знака.
- При создании аукциона задаются индекс NFT в коллекции, номерной знак/описание для интерфейса, URL метаданных, стартовая цена, минимальный шаг ставки и время окончания.
- Ставки принимаются в TON только до времени окончания.
- Новая ставка должна быть выше текущей максимальной минимум на заданный шаг.
- Ставка должна поступить от отправителя транзакции; нельзя принимать адрес участника из произвольного поля сообщения.
- Когда ставку перебивают, контракт немедленно отправляет прежнему лидеру всю его прежнюю ставку. Комиссия сети оплачивается отдельно из прикреплённого к новой ставке TON, а не вычитается из возвращаемой суммы.
- Состояние лидирующей ставки обновляется атомарно в транзакции приёма новой ставки до отправки возврата.

## Безопасность немедленного возврата

В TON исходящий перевод — отдельное асинхронное сообщение: контракт не может синхронно удостовериться, что кошелёк участника получил средства. Поэтому:

1. Контракт инициирует возврат в той же транзакции, в которой принимает новую ставку.
2. Для возврата используется bounce-enabled сообщение и отдельный идентификатор операции.
3. Если возврат отклонён и сообщение возвращается (bounce), контракт восстанавливает сумму как долг перед прежним участником.
4. Участник может забрать восстановленный долг отдельной операцией claimRefund.
5. Пока долг не выплачен, эти средства не считаются доходом аукциона и не могут быть распределены создателю, казначейству или фонду.

Таким образом, возврат инициируется сразу; если принимающий адрес не может принять сообщение, сумма не теряется и остаётся доступной для повторного получения.

## Завершение и выпуск NFT

- До времени окончания аукцион нельзя завершить.
- После окончания любой пользователь может вызвать завершение; это не должно зависеть от доступности кошелька создателя.
- Если ставок не было, аукцион закрывается без mint.
- Если победитель есть, Auction Manager отправляет в коллекцию DeployNft с адресом победителя как ownerAddress, правильным itemIndex и индивидуальным путём метаданных.
- Выпуск возможен только после того, как Auction Manager назначен администратором коллекции. До этого момента контракт можно разрабатывать и тестировать в изолированных тестах, но нельзя передавать ему права на действующую коллекцию.
- Одного факта успешной транзакции `DeployNft` в коллекцию недостаточно: коллекция лишь отправляет отдельное исходящее сообщение NFT-контракту, и его инициализация может завершиться bounce.
- Поэтому до включения выплат нужен подтверждающий протокол: коллекция сохраняет ожидающий `queryId` и адрес Auction Manager; NFT Item после успешной инициализации отправляет коллекции подтверждение с `queryId` и `itemIndex`; коллекция пересылает подтверждение Auction Manager. При bounce сообщения инициализации коллекция отправляет Auction Manager отказ. Auction Manager распределяет ставку только после подтверждения успешной инициализации NFT Item.
- Подтверждение должно быть защищено проверкой адреса NFT Item, вычисленного коллекцией для зарезервированного индекса, и проверкой ожидающего `queryId`. Неизвестные и повторные подтверждения не должны запускать выплаты.
- Для каждого аукциона индекс NFT резервируется заранее; два аукциона не должны использовать один индекс.
- Метаданные и изображение номерного знака должны быть опубликованы и проверены до запуска торгов.

## Распределение победившей ставки

После успешного выпуска NFT выигравшая ставка распределяется:
- 50% — создателю;
- 30% — казначейству (treasury);
- 20% — фонду разработки и безопасности.

Адреса treasury и фонда пока не заданы. Их нельзя подменять адресом создателя. Они должны быть заданы в конфигурации/инициализации контракта и проверяться до запуска аукционов.

Округление долей выполняется в пользу заранее определённого правила, чтобы сумма выплат никогда не превышала выигравшую ставку; остаток от округления направляется создателю.

## Защита от повторов и некорректных состояний

- Каждое сообщение, влияющее на деньги, имеет queryId/уникальный идентификатор.
- Один аукцион может перейти в состояние завершения только один раз.
- Нельзя делать выплаты до подтверждения успешного mint (по факту успешной транзакции коллекции/обработки результата).
- Повторное сообщение о завершении не должно повторно выпускать NFT или повторно распределять средства.
- Нельзя менять победителя или принимать ставки после окончания.
- Все переходы состояний и bounce-сценарии должны покрываться тестами.

## Этапы реализации

1. Зафиксировать модель данных, сообщения и состояния аукциона.
2. Реализовать контракт и wrapper на Tolk.
3. Добавить тесты: создание, ставка, перебивание и возврат, bounce возврата, окончание, отсутствие ставок, mint победителю, распределение 50/30/20, повторные сообщения и неавторизованные вызовы.
4. Собрать контракт и прогнать тесты Acton.
5. Развернуть отдельный Auction Manager в TON Testnet и проверить его отдельно.
6. Только после аудита и тестов передать ему admin NFT Collection сообщением ChangeCollectionAdmin (opcode 0x00000003).
## Совместимость с уже развёрнутой коллекцией

Текущая Testnet-коллекция была развёрнута с кодом NFT Collection/NFT Item, который не реализует подтверждение инициализации NFT. Изменение исходников в GitHub не меняет код уже развёрнутого контракта в блокчейне. Поэтому безопасная схема подтверждений не может быть включена в текущую коллекцию задним числом.

До интеграционного тестирования Auction Manager необходимо:
1. Обновить исходники NFT Collection и NFT Item, добавив защищённый протокол подтверждения успешной инициализации и обработки bounce.
2. Собрать и протестировать новую версию коллекции и NFT Item.
3. Развернуть отдельную совместимую коллекцию в TON Testnet. Текущая коллекция остаётся нетронутой; на ней пока нет выпущенных NFT, поэтому перенос NFT не требуется.
4. Проверить подтверждение на реальных тестовых транзакциях и только после этого подключать Auction Manager.

Адрес новой коллекции нельзя заранее подставлять в конфигурацию: он фиксируется только после успешного Testnet deployment и проверки getter-ов. Адрес текущей коллекции не должен использоваться для Auction Manager, пока она не поддерживает протокол подтверждения.
